The Hikoo REST API gives you the data you see in the dashboard: AI citations, prompts, competitors, sources, audits, site health, AI-crawler traffic and outreach. It is the same surface the [MCP server](/guides/mcp/overview) uses, so anything an assistant can do through MCP, your code can do too.

## Base URL

```
https://api.tryhikoo.com/api/v1/public
```

Every endpoint lives under this prefix. Requests and responses are JSON.

## Your first call

<Steps>
  <Step title="Create an API key">
    In the [dashboard](https://app.tryhikoo.com), open **Settings > API keys** and click **Create key**. Copy it right away: it starts with `hk_` and is shown only once. See [Authentication](/api-reference/authentication).
  </Step>
  <Step title="Find your website ID">
    Most endpoints work on one website. List the workspaces and websites your key can reach:

    ```bash
    curl "https://api.tryhikoo.com/api/v1/public/workspaces/with-websites" \
      -H "Authorization: Bearer $HIKOO_API_KEY"
    ```

    Note the `id` of the website you want.
  </Step>
  <Step title="Read your data">
    Pass the ID as `website_id`. This call lists the last month of ChatGPT and Perplexity citations:

    ```bash
    curl -G "https://api.tryhikoo.com/api/v1/public/citations" \
      -H "Authorization: Bearer $HIKOO_API_KEY" \
      --data-urlencode "website_id=123" \
      --data-urlencode "time_range=1m" \
      --data-urlencode "platforms[]=ChatGPT" \
      --data-urlencode "platforms[]=Perplexity"
    ```
  </Step>
</Steps>

## Conventions

<AccordionGroup>
  <Accordion title="Website-scoped endpoints" icon="globe">
    Data endpoints take a required `website_id` query parameter. The key must belong to a member of the website's workspace, and the website needs an active subscription, otherwise the API answers `403`. Discovery endpoints (`/me`, `/workspaces`, `/websites`) need no `website_id`.
  </Accordion>
  <Accordion title="Reads and writes" icon="pencil">
    `GET` requests only need workspace membership. `POST`, `PUT`, `PATCH` and `DELETE` also need a role that can edit. A key owned by a read-only member gets `403` on every write.
  </Accordion>
  <Accordion title="Quotas" icon="gauge">
    Actions that spend plan resources (prompts, competitors, audits, health refreshes, content gaps) have a matching `quota` endpoint. Check it before you act. Your plan sets the limits.
  </Accordion>
  <Accordion title="Dates and times" icon="calendar">
    Timestamps are ISO 8601 in UTC. Date filters (`date_from`, `date_to`) take `YYYY-MM-DD` and win over `time_range` when both are set.
  </Accordion>
</AccordionGroup>

## REST API or MCP?

Both use the same key, the same rate limit and the same permissions.

- **REST API**: your own code, scheduled jobs, BI dashboards, warehouse syncs.
- **MCP server**: AI assistants such as Claude or ChatGPT exploring your data in a conversation. See the [MCP setup guide](/guides/mcp/setup).
